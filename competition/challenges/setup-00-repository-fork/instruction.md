## 一、题目背景

后续代码题通过参赛仓库和实际代码版本接收实现。本题确认仓库可读取并保留 PowerContext 的来源关系，满足要求得 10 分。

## 二、任务与要求

按参赛指南使用 GitHub Import repository 导入 PowerContext，保留提交历史，通常设为私有并授予平台读取权限。已有公开 Fork 可以直接使用，无需重新导入。

仓库须存在、能够读取，且不是官方上游仓库本身，并满足以下任一来源条件：

- GitHub 保留官方 Fork 关联，包括间接 Fork；源仓库 ID 为 `1093180734`。
- 仓库至少一个分支的历史包含冻结基线，分支当前提交可以就是基线本身。

仓库名称和分支名称不限，无需创建判题专用分支、修改代码、创建 PR 或新增 commit。仅复制文件后重建历史，不满足基线历史这一条件。准备题的来源证明分支与代码题的实际评测分支可以不同。

## 三、提交方式

提交仓库 HTTPS URL，允许末尾的 `.git` 或 `/`，不填写分支页面地址，不在公开材料中放入令牌或密码。私有仓库按赛事约定方式授予读取权限。

```text
https://github.com/participant/powercontext
```

与代码题一起提测时，填写包含实现的分支或 commit；未填写时将读取默认分支。仓库准备检查不会自动替你切换代码分支。

## 四、评分与公开自检

全部条件满足得 10 分，否则得 0 分。GitHub 网络或认证故障不作为有效的零分结论。

在仓库根目录执行本地历史检查：

```bash
make -C competition check-baseline
```

该命令检查已获取的分支或 HEAD 是否包含冻结基线。浅克隆须先获取相关历史；本地结果不能替代 GitHub 可读性及仓库来源检查。官方 Fork 即使尚未获取基线，也可以按 Fork 关联满足来源要求。最终以平台验收为准。
