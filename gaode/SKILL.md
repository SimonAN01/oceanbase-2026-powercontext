# 周边去哪儿

## 理解请求

使用给定的城市和起点经纬度，保持高德要求的 `经度,纬度` 顺序。有坐标时直接使用，别用地名重新定位。只有缺少坐标时才用城市和起点名称定位。起点缺失或有多个同名地点时，请用户补充能区分的位置。

从请求中提取地点类型、必选和排除条件、步行时间上限、数量及排序偏好。最多推荐 3 个，用户要求更少时遵从。把步行上限换成秒，在排序和展示前核对。

## 查询与筛选

1. 调用高德周边搜索 `maps_around_search`，把起点传入 `location`，用用户要找的地点类型和明确条件生成 `keywords`，设置以米计的 `radius`。可先搜 1 公里。步行上限较短时可缩小搜索，允许走较久或初次结果不足时可扩大一轮。搜索半径只用于找候选，最终以路线为准。
2. 从高德返回中筛选类型匹配的地点，按 POI ID 去重。保留真实名称、地址和坐标，排除坐标缺失或明确不符的候选。类别用词太窄时，可换同义词补搜一轮，仍执行原来的限制。对优先近的请求，从较近的候选开始查路线。
3. 对每个拟推荐的候选，调用 `maps_direction_walking`。`origin` 固定为用户起点，`destination` 使用该 POI 的返回坐标。用同一条步行方案的 `distance` 和 `duration`，单位分别为米和秒。只接受有有效距离与耗时的路线。`duration` 超过用户上限就排除该地点，等于上限可以保留。路线失败时继续核查其他候选。候选是从同一起点出发的独立选项。
4. 用户偏好就近时按实际步行耗时升序，同耗时再按步行距离排序。其他偏好仅依据高德返回的信息排序。未指定偏好时，先看类型匹配，再看步行耗时。未核实的条件不得当作满足。最终输出数量不得超过用户要求及 3 家上限。

## 返回推荐

说明起点，然后逐项给出地点名称、地址、预计步行距离、预计步行时间和一句基于工具数据的推荐理由。距离、时长来自同一条路线。时长可用「约 X 分 Y 秒」表示。若工具缺少地址，注明「地址未返回」，保留工具给出的其他有效字段。

营业、排队、安静程度等只有在工具提供相应依据时才能确认，否则标注「未核实」。如果找不到足够结果，说明已核验的数量和限制。若查询成功但没有合格路线，说明在已查询范围内没有找到符合条件的地点，并可建议放宽一个限制。若高德请求失败，说明此次无法核验哪些信息。没有查到的地点、地址和步行数据不要补写。
